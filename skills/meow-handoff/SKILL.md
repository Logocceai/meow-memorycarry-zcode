# 会话交接(meow-handoff)

把本窗口有价值的信息**总结后规范化带走**。记忆库位于当前仓库根 `.zcode/memory/`。档位骨架见本技能目录 `docs/tier-system.md`(下称"骨架"),格式规范见 `docs/format-spec.md`(下称"规范")。

## 双轴档位

### 速度轴(用户主观选择,默认 `s2`)

| 代号 | 名称 | 生成策略 | 读取力度 | 快照上限 | 检查与报告 |
|---|---|---|---|---|---|
| `s1` | 速度 | 骨架直填、一次成型不复读、免策划措辞 | 扫读 | ≤40 行 | 跳过 plans 扫描与格式自检;git 未提交只一句话提醒不等待;报告 ≤3 行 |
| `s2` | 平衡(默认) | 标准撰写 | 常读 | ≤150 行 | 标准:写前 git 检查、行数基本控制、标准报告 |
| `s3` | 质量 | 精炼撰写 + 写后自检 | 精读 + 交叉检查 | ≤150 行 | 完整自检(命名、summary 同源、六节、行数)+ 详细报告 |

### 深度轴(默认由 AI 按上下文量决定)

| 代号 | 名称 | 读取范围 | 吸收与归档 |
|---|---|---|---|
| `d1` | 节约 | 仅 INDEX | 不吸收;不改变任何旧快照状态 |
| `d2` | 平衡 | INDEX + 本次相关分层;旧快照仅读 frontmatter | 相关旧快照标 `absorbed`;超 14 天归档 |
| `d3` | 深度 | 全部分层 + 全部快照 | 全量吸收合并 + 去重 + 行数上限;全量归档 |

两轴交叉的 9 种组合行为见骨架 §3。**范围永远由深度轴定,力度永远由速度轴定。**

## 执行流程

1. **定位记忆库**
   - 记忆库 = 当前仓库根的 `.zcode/memory/`。
   - 不存在时:从本技能目录 `templates/` 初始化——复制 INDEX.md、project.md、facts.md、decisions.md、lessons.md,创建空的 `handoffs/` 与 `archive/`,时间占位替换为当天。

2. **解析参数与推荐**
   - 按骨架 §4 解析:`sN` / `sNdM`(连写) / `sN dM` / `dM` / 纯数字(旧用法=深度轴);`tidy` 跳第 8 步。
   - 速度轴缺省取 `s2`,不推荐。
   - 深度轴缺省时按下列依据推荐,输出"推荐 dN + 一句话理由",等待用户确认或改档后继续:
     - 推荐 `d3`:会话明显很长或接近上下文上限;任务复杂未完成需新窗口无缝接续;存在多个 active 旧快照;上次交接是 `d1`
     - 推荐 `d2`:常规收尾
     - 推荐 `d1`:信息量小、上下文充裕、惯例性存档

3. **收尾前检查**(速度轴控制)
   - `git status` 有未提交改动:`s2`/`s3` 提示先 `/checkpoint` 并等待确认;`s1` 一句话提醒后直接继续。
   - `.zcode/plans/` 扫描:仅 `s2`/`s3` 执行;`s1` 跳过。

4. **回顾提炼**(速度轴控制力度)
   - 四类信息:完成 / 决策 / 坑 / 下一步;一句话概括(≤20 字,充当文件名、正文标题与 `summary` 三者同源)。
   - `s1` 每条一句话直填;`s2` 标准压缩;`s3` 精炼并复查措辞。条目一律按规范 §2:一条一事、`[YYYY-MM-DD]` 前缀、自包含、中文。

5. **写交接快照** `handoffs/<概括>.memo.md`
   - 结构按 `templates/handoff-snapshot.md` 六节:Summary / Done / Decisions / Pitfalls / Next / Refs;frontmatter 四字段(`summary`、`created`、`updated`、`status: active`)。
   - 长度:`s1` ≤40 行;`s2`/`s3` ≤150 行。命名与非法字符清理见规范 §4。

6. **处理记忆库**(深度轴定范围,速度轴定读取力度)
   - `d1`:只刷新 INDEX;不读分层文件、不吸收、不改变旧快照状态。
   - `d2`:读 INDEX 与本次相关分层;把内容吸收进对应分层文件(project 必更新;decisions/lessons/facts 有则更新);相关旧快照标 `absorbed`;`absorbed` 且 `created` 超 14 天的 `git mv` 进 `archive/` 并改 `status: archived`。
   - `d3`:通读全部分层与全部快照;全量吸收合并、去重、执行行数上限;确认信息已吸收后全部旧 active 标 `absorbed`;超期归档。
   - 读取方式随速度轴:`s1` 扫读取要点,`s2` 常读,`s3` 精读且读后交叉检查一致性。

7. **刷新 INDEX**(所有档位共用):活跃任务 ≤5 与下一步 ≤3 按第 4 步提炼刷新;本次新快照加入"最近快照"(≤5 条,按 created 倒序);全文件 ≤80 行。

8. **整理模式**(仅 `tidy`):去重分层文件(同一内容只保留最早一条)、合并同类、执行行数上限、把所有 `absorbed` 超 14 天的快照 `git mv` 进 `archive/` 并改 `status: archived`、重建 INDEX(≤5 条,只列真实存在的快照),不新增任何记忆内容。

9. **写后自检与入库报告**
   - `s3` 执行自检清单:文件名合法且以 `.memo.md` 结尾、`summary` 与文件名一致、六节齐全、行数在上限内、新快照已列入 INDEX、状态值正确。
   - 仓库由 git 跟踪时 `git add .zcode/memory/`(不自动 commit,提交由用户走 `/checkpoint`)。
   - 报告:`s1` ≤3 行(档位 + 文件 + 下一步);`s2` 标准(档位、新建/更新文件、归档、INDEX 摘要);`s3` 标准 + 自检结果明细。`d1` 时注明"细节未吸收,下次较深交接会处理"。结尾提示"新窗口可用 `/recall` 载入本快照继续"。

## 边界

- 只写 `.zcode/memory/` 及其 `archive/`,不改任何代码与其他文件。
- 不删除记忆文件;归档一律 `git mv`,历史由 git 保留。
- 只记录本窗口真实发生的信息;禁止编造,禁止把未验证的猜测写成事实。
- 不自动执行 git commit;推荐模式下未经用户确认不擅自执行交接。
