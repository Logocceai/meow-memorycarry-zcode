# 会话交接(meow-handoff)

把本窗口有价值的信息**总结后规范化带走**。记忆库位于当前仓库根 `.zcode/memory/`,格式、命名与行数上限遵循本技能目录下 `docs/format-spec.md`(下称"规范")。

## 交接档位

| 档位 | 名称 | 做什么 | 不做什么 | 适合场景 |
|---|---|---|---|---|
| 1 | 节约 | 精简快照 + 刷新 INDEX | 不读不写分层文件、不吸收旧快照 | 信息量小、上下文充裕、惯例性存档 |
| 2 | 平衡 | 完整快照 + 更新本次相关的分层文件 + 吸收相关旧快照 + 刷新 INDEX | 不全量通读、不做全面去重 | 常规收尾(默认推荐) |
| 3 | 深度 | 全量通读分层文件与全部 active 快照,完整吸收合并、去重、执行行数上限,再写高质量快照 + 刷新 INDEX | — | 长任务换窗、上下文接近上限、需要新窗口无缝接续 |

档位只影响**更新深度**,不影响格式:三个档位的快照都遵守规范(档位 1 允许压缩 Done/Decisions,Pitfalls 可为"无",Next 必写)。档位 1 写出的快照照常标 `status: active`,细节留待下次档位 2/3 交接时吸收。

## 执行流程

1. **定位记忆库**
   - 记忆库 = 当前仓库根的 `.zcode/memory/`。
   - 不存在时:从本技能目录 `templates/` 初始化——复制 INDEX.md、project.md、facts.md、decisions.md、lessons.md 到记忆库根,创建空的 `handoffs/` 与 `archive/`,frontmatter 占位(`<初始化时间>`、`<最后更新时间>`)替换为当天时间。

2. **解析参数**
   - `1` / `2` / `3`:直接执行对应档位,进入第 3 步。
   - `tidy`:跳到第 8 步(整理模式)。
   - 无参数:**推荐模式**——按下列依据选出推荐档位,用两三行输出"推荐档位(名称)+ 一句话理由 + 其他备选",询问"按推荐执行,还是换档?";用户确认或改档后继续。
     - 推荐 3:会话明显很长或接近上下文上限;任务复杂未完成、新窗口需要无缝接续;`handoffs/` 中存在多个 active 旧快照;上次交接是档位 1
     - 推荐 2:常规收尾,本次会话有一定信息量
     - 推荐 1:本次信息量小;上下文充裕;用户只想惯例存档

3. **收尾前检查**
   - `git status` 有未提交的代码改动:提示用户先执行 `/checkpoint`(记忆库只存知识与状态,不存代码),用户明确跳过才继续。
   - `.zcode/plans/` 中有本会话相关的 plan 文件:记下路径,写入快照 Refs。

4. **回顾本窗口,提炼四类信息与一句话概括**——这是产出质量的根源,宁缺毋滥:
   - 完成:做了什么,改动落在哪些文件与提交
   - 决策:拍板了什么,为什么
   - 坑:踩了什么,怎么解决的
   - 下一步:任务断点在哪,新会话第一件事做什么
   - **概括**:给本次交接提炼一句话(建议 ≤20 字,如"记忆库初始化与v1实现"),它将同时充当快照文件名、正文标题与 frontmatter `summary`

   每条信息按规范 §2 压缩后再入库:一条一事、`[YYYY-MM-DD]` 日期前缀、自包含(写具体路径/命令/hash,不写"刚才那个问题")、总结体、中文。档位 1 可在此步适度精简。

5. **写交接快照** `handoffs/<概括>.memo.md`(命名与非法字符清理规则见规范 §4),结构按 `templates/handoff-snapshot.md` 六节:Summary / Done / Decisions / Pitfalls / Next / Refs,全文件 ≤150 行;frontmatter 四字段:`summary`(与文件名、正文标题同源)、`created`、`updated`、`status: active`。

6. **按档位处理记忆库**
   - **档位 1**:只刷新 INDEX(活跃任务/下一步/最近快照);不动分层文件,不改变任何旧快照的状态。
   - **档位 2**:更新与本次任务相关的分层文件——`project.md` 必更新"进行中"状态,`decisions.md` 追加新决策,`lessons.md`/`facts.md` 有新增则更新(写入前对照规范 §5 行数上限);把内容已被吸收的旧 active 快照标 `absorbed`;`absorbed` 且 `created` 超 14 天的 `git mv` 进 `archive/` 并改 `status: archived`;刷新 INDEX。
   - **档位 3**:先通读全部分层文件与全部 active 快照 → 完整吸收合并进分层文件(去重、执行行数上限、删被取代的旧条目)→ 确认每份旧 active 快照的信息都已吸收后标 `absorbed` → 超 14 天的归档 → 刷新 INDEX。等价于"tidy + 完整交接"。

7. **刷新 INDEX.md**(所有档位共用):活跃任务 ≤5 与下一步 ≤3 依据第 4 步提炼刷新;本次新快照加入"最近快照"列表(≤5 条,按 created 倒序);全文件 ≤80 行。

8. **整理模式**(仅 `tidy`):去重并合并分层文件条目、执行行数上限、把所有 `absorbed` 超 14 天的快照 `git mv` 进 `archive/` 并改 `status: archived`、重建 INDEX.md,不新增任何记忆内容。

9. **入库与报告**
   - 仓库由 git 跟踪时:`git add .zcode/memory/`(不自动 commit,提交由用户走 `/checkpoint`)。
   - 输出报告:本次档位与名称、新建/更新的文件、归档的快照、INDEX 当前的活跃任务与下一步;档位 1 需注明"细节未吸收,下次较深交接会处理";结尾提示"新窗口可用 `/recall` 载入本快照继续"。

## 边界

- 只写 `.zcode/memory/` 及其 `archive/`,不改任何代码与其他文件。
- 不删除记忆文件;归档一律 `git mv`,历史由 git 保留。
- 只记录本窗口真实发生的信息;禁止编造,禁止把未验证的猜测写成事实。
- 不自动执行 git commit;推荐模式下未经用户确认不擅自执行交接。
