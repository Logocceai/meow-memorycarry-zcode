# 档位体系(基础骨架)

本文档定义 meow-memorycarry-zcode 交接的**双轴档位骨架**,是 `SKILL.md`、`format-spec.md` 等实现文件的唯一依据;实现与本文档冲突时,以本文档为准。

## 1. 设计原则

- **正交性**:两轴各自独立——一个轴的取值不改变另一个轴的定义,任意组合都有明确语义。
- **单一职责**:速度轴管**过程方式**(怎么写),深度轴管**内容范围**(写什么范围)。
- **默认收敛**:不指定时有明确缺省,零参数或单参数即可衔接主流用法(深度轴缺省时由 AI 推荐并经用户确认;无法交互时按 SKILL.md 的非交互条款继续)。
- **可扩展**:新增档位或新轴必须满足 §7 的扩展规则;禁止在实现文件里私有定义档位。

## 2. 两轴定义

### 2.1 速度轴 speed(代号 `s`)——用户主观选择

决定压缩过程的**方式**:生成策略、读取力度、快照长度上限、检查步骤、报告详细度。

| 代号 | 名称 | 生成策略 | 读取力度 | 快照上限 | 检查与报告 |
|---|---|---|---|---|---|
| `s1` | 速度 | 骨架直填(按 §6 骨架逐节填充)、一次成型不复读、免策划措辞 | 扫读(快速掠过取要点) | ≤40 行 | 跳过 plans 扫描与格式自检;git 未提交改动自动单次提交(含推送,失败不阻塞);报告 ≤3 行 |
| `s2` | 平衡(默认) | 标准撰写 | 常读 | ≤150 行 | 标准:写前 git 检查并按领域分组自动提交、行数基本控制、标准报告 |
| `s3` | 质量 | 精炼撰写 + 写后自检 | 精读 + 交叉检查(读后对照校验一致性) | ≤150 行 | 完整自检清单(命名合法、summary 与文件名同源、六节齐全、行数上限)+ 详细报告 |

### 2.2 深度轴 depth(代号 `d`)——默认由 AI 客观决定

决定压缩的**内容范围**:读哪些文件、吸收哪些旧快照、归档动作。

| 代号 | 名称 | 读取范围 | 吸收 | 归档 |
|---|---|---|---|---|
| `d1` | 节约 | 仅 INDEX | 不吸收;不改变任何旧快照状态 | 不归档 |
| `d2` | 平衡 | INDEX + 本次相关的分层文件;旧快照仅读 frontmatter | 相关内容已被吸收的旧快照标 `absorbed` | `absorbed` 且 `created` 超 14 天归档 |
| `d3` | 深度 | 全部分层文件 + 全部快照 | 全量吸收合并 + 去重 + 行数上限 | 全量归档(计时同按 `created`) |

**Aspect 边界**:范围(读哪些、吸收哪些)永远由深度轴定;力度(读得多细、写得多精)永远由速度轴定。两轴不越界。

## 3. 组合矩阵(9 种)

行 = 深度轴,列 = 速度轴。每格为完整、独立的行为语义:

| 深度 \ 速度 | `s1` 速度 | `s2` 平衡 | `s3` 质量 |
|---|---|---|---|
| `d1` 节约 | **极速存点**:只写精简快照(≤40 行)+ INDEX,一扫一填即走,不读分层、不吸收 | **快速记录**:精简快照 + INDEX,标准措辞 | **精修快照**:仍不吸收,但写后自检格式完整性 |
| `d2` 平衡 | **快速交接**:范围照常(读相关分层、吸收相关快照),全部快速撰写与扫读 | **默认:标准交接** | **精细交接**:标准范围 + 精读 + 自检 + 详细报告 |
| `d3` 深度 | **快速整合**:全量吸收去重,但扫读 + 快写,报告一句话 | **完整交接**:全量吸收,标准撰写 | **最高质量**:全量吸收 + 精读 + 交叉检查 + 完整自检 + 详细报告 |

## 4. 调用语法

**主形式(速度在前,深度在后可选):**

```
/handoff sN          # 指定速度档,深度由 AI 按上下文量决定(最常用)
/handoff sNdM        # 连写:两个档位一次指定,如 /handoff s1d3
/handoff sN dM       # 空格分隔等价形式
/handoff dM          # 只指定深度档,速度默认 s2(兼容旧习惯)
/handoff             # 全默认:速度 s2 + AI 推荐深度
/handoff tidy        # 整理模式(不参与双轴)
```

**缺省规则:**

| 情形 | 速度轴 | 深度轴 |
|---|---|---|
| 未指定速度 | `s2` 平衡 | — |
| 未指定深度 | — | AI 按上下文量与会话状态推荐(推荐依据见 SKILL.md) |

**解析优先级**:连写(`s1d3`) > 空格(`s1 d3`) > 单代号;无 `d`/`s` 前缀的纯数字(如旧的 `/handoff 2`)一律解析为深度档(旧用法兼容)。

**边界写法**:两轴顺序无关,`d3 s1` 与 `s1 d3` 等价;只写一个数字时按上条作深度档(`s1 3` 等价于 `s1 d3`);`tidy` 与档位同时出现时档位被忽略(tidy 不参与双轴)。

**自然语言别名**(AI 理解即可,不要求逐字):速度/speed→`s1`、平衡/balanced→`s2`、质量/quality→`s3`;节约→`d1`、深度→`d3`。`d2` 没有单性别名——"平衡"按速度轴解析(用户主观轴优先),深度轴要写 `d2` 或"深度平衡"。

**书写规范**:在文档与报告里提及档位时带轴前缀(如"速度轴·平衡 `s2`"),避免两个"平衡"混淆;纯代号书写时 `s` 恒在前。

## 5. 执行流程 × 轴归属

| 步骤 | 受控于 |
|---|---|
| 1 定位记忆库(不存在则初始化) | — |
| 2 解析参数与推荐 | 输入(两轴缺省规则见 §4) |
| 3 收尾前自动提交(git / plans) | **速度轴**:`s1` 单次提交、跳过 plans 扫描;`s2/s3` 按领域分组提交 |
| 4 回顾提炼与概括 | **速度轴**:压缩力度与措辞投入(`s1` 骨架直填) |
| 5 写交接快照 | **速度轴**:策略与长度上限(40/150/150) |
| 6 处理记忆库(读取/吸收/归档) | **深度轴**定范围;**速度轴**定读取与撰写力度 |
| 7 刷新 INDEX | 共用(所有档位一致) |
| 8 整理模式(tidy) | —(独立入口) |
| 9 入库与报告 | **速度轴**:报告详细度(`s1` ≤3 行) |

## 6. 加速机制(供实验验证)

速度轴缩短压缩时间的四个真实杠杆:

1. **输出量**:快照长度上限(§2.1)与报告长度直接决定输出 token;
2. **推理开销**:骨架直填免去结构策划与措辞打磨(`s1`);
3. **工具往返**:跳过 plans 扫描、格式自检等步骤,减少调用轮次(`s1`);
4. **读取力度**:扫读/常读/精读决定输入 token 的深度(`s1`/`s2`/`s3`)。

## 7. 扩展规则

未来新增档位或新轴必须满足:

1. **正交性检查**:新维度与现有两轴的职责不重叠;若与某轴相关,应扩展该轴的档位而非新增轴。
2. **命名冲突检查**:新档位名不得与现有档位名重复(含中英文);代号不得与 `s`/`d` 冲突。
3. **默认值规则**:每个新档位参数必须有明确缺省值,或规定由 AI/用户哪方决定。
4. **矩阵补全**:新增档位必须补全组合矩阵中所有格的独立语义,不允许"与某档相同"。
5. **单一来源**:先改本文档,再同步全部实现与分发文件——`SKILL.md`、`format-spec.md`、`commands/`、`README.md`、`docs/user-guide.md`、`INSTALL-FOR-AI.md`、`CHANGELOG.md`、`marketplace.json`、本机安装副本(`.zcode/skills/`、`.zcode/commands/`,改动后重跑 `scripts/install.ps1` 同步)与发布 zip,禁止实现先行。
