# 记忆载入(meow-recall)

从记忆库把历史窗口的进度"带回来":**先按时间列出快照清单,由用户选择,再载入详情**——不擅自决定载入哪份。

## 执行流程

1. **定位记忆库**:当前仓库根 `.zcode/memory/INDEX.md`。
   - 不存在 → 告知用户该仓库还没有记忆库,询问是初始化(由 `/handoff` 首次执行时创建)还是直接开始新任务;不擅自创建。

2. **列快照清单**(只读 frontmatter,不深读内容):
   - 扫描 `handoffs/*.memo.md`,读取每份的 `summary` / `created` / `status`(字段缺失时用文件名代替 summary、文件系统时间代替 created,并在清单中标注)
   - 按 `created` 倒序(新在上)输出编号清单:

     ```
     1. [2026-09-15 08:27] 记忆库初始化与v1实现(active)
     2. [2026-09-14 17:40] 确定记忆格式规范(absorbed)
     ```

   - 清单为空时明确说"记忆库还没有任何交接快照",并停在第 3 步等用户决定
   - 清单超过 15 条时只列最近 15 条,并提示"更早的快照建议先 /handoff tidy 归档"(tidy 会归档超期的已吸收快照,以及长期未吸收的 active 快照)
   - 参数为 `latest` 或用户已明说"继续上次/最新"时,跳过等待直接选定第 1 份

3. **等待用户选择**:请用户输入序号(可多选,如 `1,3`),或直接回车选最新一份。**没有用户选择不擅自加载**(参数 `latest` 除外)。
   - 客户端提供选项式提问工具(如 AskUserQuestion)时可用它代替文本输入:每份候选快照一个选项,另附"载入最新一份"选项;仍须用户确认后才载入。
   - **非交互场景**(无人在场、批处理):等同 `latest`,在摘要首行注明这是自动选择。

4. **载入所选内容**:
   - 所选快照全文(多选时全部)
   - `project.md`:项目状态
   - `decisions.md` / `lessons.md` / `facts.md`:与所选快照任务相关的条目(单文件 ≤120 行,可整读)

5. **输出载入摘要**,固定三段、全摘要 ≤30 行(多选时按快照顺序依次给要点,总量仍不超 30 行):
   - **上次进度**:所选快照的 Summary 与 Done 要点
   - **相关决策与教训**:只列与本次任务直接相关的条目
   - **下一步建议**:快照 Next 与 INDEX"下一步"的合并

   摘要末尾向用户确认"从哪里继续",得到答复再动工。

6. **更新会话标题**:把当前会话在左栏显示的标题改成所选快照的概括——调用本技能目录下的脚本(仓库级安装路径为 `.zcode/skills/meow-recall/scripts/set-session-title.mjs`):

   ```bash
   node scripts/set-session-title.mjs "<快照 summary>"
   ```

   - 标题取所选快照的 `summary`(≤20 字,天然适合);多选时取最新一份的。
   - 脚本同时改写 `tasks.title` 与该行的 `meta_json.title`:客户端运行中会以 meta 为源重建任务行,只改列会被下一次落盘冲回旧值(2026-09-16 实测)。标题被冲回时重跑同一条命令即可,脚本会报告"修复被冲掉的标题"。
   - 为什么需要:`/recall` 只有 7 个字符,低于 ZCode 标题生成的最小输入守卫,不处理的话左栏会永久显示 `/recall`。
   - 脚本最后会尽力调用客户端自己的 `renameTask`(经 CDP),让侧边栏**当场刷新**;这条依赖客户端带调试端口(默认 9222)且渲染层结构未变,不可得时自动跳过,届时标题在**下次打开客户端或切换工作区后**显示。报告里如实转述脚本最后一行,别说成"一定能免刷新"。
   - 脚本失败(定位不到会话、库不可写)只提示一句,**不阻塞后续流程**。

7. **继续任务**:按确认的起点执行;本窗口产生的新信息由 `/handoff` 在收尾时带走。

## 边界

- 第 2-3 步只读 frontmatter 与 INDEX,不修改记忆文件(写入是 `/handoff` 的职责)。
- 第 6 步只写 ZCode 的标题字段(`session.title` + `title_source='custom'`、`tasks.title` + `meta_json.title` + `title_overridden=1`),并通过客户端自己的 `renameTask` 触发一次侧边栏刷新;不动会话内容。被标记为人工标题后该会话不再自动生成标题——对 `/recall` 会话本来也不会生成,无损失。
- 不凭空编造:清单为空、快照缺某类信息时明确说明,禁止补写臆测内容。
- 载入摘要超过 30 行说明选得太多:优先压缩为每份一行要点并提示用户下次少选几份;**不丢弃用户已确认的选择**、不回退重来。
