# meow-memorycarry 使用手册

让 AI 会话的记忆可以**带走**和**带回**:收尾时用 `/handoff` 把本窗口有价值的信息总结入库,新窗口用 `/recall` 按时间浏览历史记忆、选择载入,接着上一个任务继续干。

适用于 ZCode(其他工具在 roadmap)。全程零配置,不需要 API、不需要常驻进程。

## 一分钟上手

```powershell
# 1. 安装(在仓库根执行一次)
powershell -ExecutionPolicy Bypass -File projects/meow-memorycarry-zcode/scripts/install.ps1
```

2. 会话收尾时,在对话框输入:`/handoff`
3. 新开窗口后,输入:`/recall`

就这样。下面是需要知道的细节。

## 两条核心指令

### `/handoff` — 收尾带走

**什么时候用**:一个任务告一段落、上下文快满、准备关窗口或换窗口之前。

**它会做什么**(你会在对话里看到它逐项执行):

1. 检查有没有未提交的代码改动——有的话提醒你先 `/checkpoint`,避免代码进度和记忆进度脱节
2. 回顾本窗口,提炼四类信息:完成了什么、定了什么决策、踩了什么坑、下一步做什么
3. 生成一份交接快照,以一句话概括命名,如 `记忆库初始化与v1实现.memo.md`
4. 按档位把信息**合并**进记忆库的分层文件(档位 1 跳过这步),处理旧快照吸收与归档,刷新索引

**输出**:一份简短报告——本次档位、新建/更新了哪些文件、归档了哪些旧快照、当前活跃任务与下一步。结尾会提示你"新窗口可用 /recall 载入"。

### 交接档位怎么选

`/handoff` 有三个档位,决定"这次交接花多少力气":

| 档位 | 名称 | 花多少 | 适合什么时候 |
|---|---|---|---|
| 1 | 节约 | 只写精简快照 + 刷新索引,不读不写分层文件 | 信息量小、上下文充裕、只想惯例存档 |
| 2 | 平衡 | 完整快照 + 更新相关的分层文件 + 吸收旧快照 | 常规收尾(大多数时候) |
| 3 | 深度 | 全量通读、完整吸收合并、去重整理,再写高质量快照 | 长任务换窗、上下文快满、要无缝接续 |

用法:直接说 `/handoff 1`、`/handoff 2`、`/handoff 3`。

**不确定选哪个?** 直接输入 `/handoff` 不带档位——AI 会根据本次会话的长度、信息量和记忆库状态**推荐一个档位并说明理由**,你确认或换档即可。

档位 1 写出的快照仍然是一份完整的记忆文件,只是信息没被合并进分层文件;下次任何较深档位的交接会自动把它吸收掉,不会丢。

输入 `/handoff tidy` 则进入**整理模式**:只整理不新增,去重、压缩、把过期快照归档,适合记忆库用久了之后手动清理一次。

### `/recall` — 新窗口载入

**什么时候用**:新开窗口,想接着之前的任务干。

**交互方式**:它不是直接读最新的一份给你,而是**先列出清单让你挑**:

```
1. [2026-09-15 08:27] 记忆库初始化与v1实现(active)
2. [2026-09-14 17:40] 确定记忆格式规范(absorbed)
```

- 输入序号载入,如 `1`;也可以多选,如 `1,3`
- 直接回车 = 载入最新一份
- 已经确定要最新时,直接输入 `/recall latest` 跳过选择

载入后你会看到一段摘要:上次进度、相关决策与教训、下一步建议,末尾问你"从哪里继续"。确认后 AI 开始干活。

## 典型工作流

```text
新窗口 A                     旧窗口 B(上下文 70% 了)
─────────────────────────    ──────────────────────────────
/recall                      /checkpoint   ← 先提交代码
  ↓ 列出快照清单               /handoff      ← 再交接记忆
  选 1,确认继续点              ↓ 生成快照,提示"可用 /recall 载入"
  ↓ 干活...                    关掉窗口
  ↓
任务收尾(或上下文到 70-80%)
  ↓
/checkpoint → /handoff → 关窗口 → 新窗口 /recall ...
```

## 什么时候该交接

- **上下文用量到 70-80%**:当前任务收尾后换窗口,这是最主要的时机(接近上限时优先保证交接质量,不要继续硬撑)
- **一个里程碑完成**:功能写完、bug 修完、方案敲定
- **踩完坑之后**:刚解决的报错和它的根因,是快照里最值钱的内容
- **当天收工前**:留一份"明天从哪继续"

不需要高频交接——那是流水账。一次有信息量的交接胜过十次敷衍的。

## 记忆库长什么样

每安装到一个仓库,记忆库固定放在 `<仓库根>/.zcode/memory/`,随仓库一起提交 git,换机器、回滚历史都靠它:

```
.zcode/memory/
├── INDEX.md      # 入口:活跃任务、下一步、最近快照(≤80 行)
├── project.md    # 项目目标、结构、进行中任务
├── facts.md      # 原子事实:环境、路径、可复用命令
├── decisions.md  # 拍板的决策 + 理由(只增不改)
├── lessons.md    # 踩坑记录:现象 / 根因 / 规避
├── handoffs/     # 交接快照,每次 /handoff 一份
└── archive/      # 过期快照归档处(git mv 移入,永不删除)
```

每个文件开头都有四个字段:一句话概括(`summary`)、创建时间(`created`)、最后更新(`updated`)、状态(`status`)。

### 快照怎么读

每份快照固定六节,新窗口 /recall 后 AI 主要靠它恢复上下文:

| 节 | 内容 |
|---|---|
| Summary | 3 句以内:本窗口干了什么 |
| Done | 已完成事项,带 commit 或文件路径 |
| Decisions | 本次拍板的决策与理由 |
| Pitfalls | 踩的坑与规避方式 |
| Next | 下一步(写成可直接执行的指令) |
| Refs | 相关文件、commit、plan 链接 |

## 常见问题

**`/recall` 说没有记忆库?**
该仓库还没执行过 `/handoff`(记忆库由首次交接自动创建)。也可能是当前会话没开在仓库根目录——记忆库按仓库走,换目录就换记忆库。

**忘了交接就关了窗口,怎么办?**
未交接的增量(决策、坑、断点)不会进记忆库。补救:如果旧窗口会话还在,回去补一次 `/handoff`;如果已经关闭,代码进度有 git 兜底,软知识只能从会话历史里找回。这也是为什么建议养成"收尾先交接"的习惯。

**记忆库会不会越来越乱、越来越大?**
有防乱机制:写入前有行数硬上限,超限必须先精简;旧快照内容被合并进分层文件后标记 `absorbed`;超过 14 天自动 `git mv` 进 `archive/` 归档(只移动不删除,历史由 git 保留)。用久了觉得乱,执行 `/handoff tidy` 手动整理一次。

**清单里的 `active` / `absorbed` 是什么意思?**
`active` = 这份快照的信息还没被完全吸收,值得优先载入;`absorbed` = 主要内容已合并进分层文件(project/decisions 等),快照本身只作存档,载入它时信息基本也能从分层文件拿到。

**每次交接都要想档位吗?**
不用。不带档位时 AI 会推荐;日常默认 2(平衡),重要换窗用 3(深度),临时存一下用 1(节约)。

**多个仓库/项目怎么用?**
每个仓库一份独立的记忆库,互不干扰。在哪个仓库开窗口,`/handoff` 和 `/recall` 就作用于那个仓库的记忆库。给其他仓库装上插件:`-Target <仓库根>` 参数即可。

**能全自动吗?**
v1 刻意做成指令触发:摘要必须总结精炼后保存,新窗口由你显式载入,可控且省 token。codex/dsh 接入与可选的自动提醒在 roadmap 里。

**安装后更新插件?**
改了技能文件后重跑一次 `install.ps1` 覆盖安装即可(幂等)。

**记忆库需要我手动提交吗?**
不用。`/handoff` 会自动 `git add` 记忆库文件,提交仍走 `/checkpoint`(与代码一起按惯例提交)。

## 命令速查

| 操作 | 输入 |
|---|---|
| 安装到当前仓库 | `powershell -ExecutionPolicy Bypass -File projects/meow-memorycarry-zcode/scripts/install.ps1` |
| 安装到其他仓库 | 同上,末尾加 `-Target <仓库根>` |
| 收尾交接(推荐档位) | `/handoff` 或说"交接一下"——AI 推荐档位,确认后执行 |
| 指定档位交接 | `/handoff 1`(节约)/ `/handoff 2`(平衡)/ `/handoff 3`(深度) |
| 整理记忆库 | `/handoff tidy` 或说"整理记忆" |
| 新窗口载入 | `/recall` 或说"接着上次" |
| 直接载入最新 | `/recall latest` |

## 边界与注意

- 记忆库存**知识与状态**,不存代码本体;代码进度归 `/checkpoint`,两者配合使用
- 记忆只记本窗口**真实发生**的事:AI 不会编造,不许把猜测写成事实;空白记忆库会如实告诉你"没有记录"
- 任何归档都是 `git mv`,永不删除文件
